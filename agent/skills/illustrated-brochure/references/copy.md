# Copy

Write for a smart stranger. Short sentences. Concrete nouns. No class names,
library names, ticket ids, or file paths unless the user asked for a technical
appendix.

Path labels for a **field-story**: “the original”, “the first rewrite”, “the
path to finish”. No personal names, product names, employer names, or repo
names. The cover kicker is the topic or document type (FIELD STORY,
A WALKTHROUGH), never the product.

## Shape

| Request | Shape |
|---------|--------|
| How this works, walk me through it, document this process | **process** |
| A vs B, which option, scorecard of choices | **comparison** |
| What went wrong, postmortem, what happened | **incident** |
| Original vs rewrite vs correct path | **field-story** |

Do not stretch a how-to into three rewrite paths. Do not flatten a rewrite
history into a generic checklist.

## Metaphor

If the domain is technical, pick **one** everyday scene (front desk, kitchen,
workshop, trail). Map every object once. Write the problem as one sentence in
that language.

Teach the surprising plot device on the scene page (the mixed-up object, the
date that jumps, the shared name on every key) before any later diagram uses
it.

If the metaphor fights the facts, change the metaphor. Do not mix two scenes.

A **process** brochure may skip the metaphor when the steps are already
ordinary language (backup, deploy, cook). Use a dictionary only when a word
would otherwise be jargon.

## Voice

- Affirmative. “The date jumps to 2074.”
- Name what went right and what went wrong on the same page as that path.
- Internals live in the project README, not the PDF.
- Cover promise: what the reader will understand, not a tease.

## Field-story pages

1. Cover — title, promise, three path cards, tiny overview.
2. Metaphor — dictionary, stacked overview, color key.
3. Original — intro, right, wrong, Dia.
4. First rewrite — intro, right, wrong, Dia.
5. Path to finish — intro, right, still open, Dia.
6. Scorecard — table plus “do this next”.

## Process pages

1. Cover — title, promise, step overview.
2. Scene — who does this, with what, dictionary if needed.
3–N. Each major step: what you do, what good looks like, Dia.
Last. The working sequence, plus the one thing to remember.

## Comparison pages

1. Cover — the question, the options at a glance.
2. Shared scene — what every option is trying to do.
3–N. One option per page.
Last. Scorecard. A recommended next step if the user asked for one.

## Incident pages

1. Cover — what broke, in one sentence.
2. Scene — the desk as it was supposed to work.
3. What happened — Dia of the failure.
4. What to keep, what to change.
Last. “Do this next.”
