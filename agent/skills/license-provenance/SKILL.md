# License and Provenance

AI-written trees need a human-readable provenance note, not a vibe.

## When this runs

- New project mostly generated by an agent
- Fork or UI restyle of a third-party codebase
- User asks "is this copy-pasted" or wants to publish

## Checklist

1. Identify every third-party file and its incoming license (read COPYING, LICENSE, headers).
2. Flag files the agent added that contain comments, identifiers, or unique strings that look copied from a known project. Search the web for distinctive literals when suspicion is high.
3. Confirm the outbound license the user wants. Do not change license text without asking.
4. List generated files that have no header and add a short SPDX + "AI-assisted, human-reviewed" header only if the project already uses headers.
5. Call out kernel, GPL-incompatible, or trademark issues (names, assets, ROM-like data) as blockers.

## Output

```
## Provenance
Inbound licenses: ...
Outbound license: ...
Third-party kept: ...
Agent-new files: <count>
Copy-risk: none | review | likely
Blockers:
- ...
Safe to publish: yes | no
```

## Rules

- Never strip copyright headers.
- Never declare a work original just because an LLM wrote it.
- Cross-check with `code-review` for structure and `ai-security-rules` for deps. This skill owns license only.
- Do not give legal advice. Label findings as engineering risk, not a legal opinion.
