# Design inspiration

Look at real work in the same job (landing, icon, footer, motion) before
generating. Two or three examples beat a palette invented from nothing.

Aesthetic identity (palette, type, anti-template tells) stays on the
**frontend-design** plugin. Matching an existing desktop stays on
**classic-ui-reskin**. This skill is the gallery index.

## Workflow

1. Name the job: landing, app screen, icon, logo, footer, motion, background,
   type, or social post.
2. Open `references/sites.md` and pick the matching row.
3. Fetch two or three current examples (titles, layout notes, type, motion).
   Account-gated galleries (Mobbin and similar): use what is visible without
   inventing screenshots from memory.
4. Write a four-line brief: subject, one reference trait to keep, one trait
   to drop, the constraint (static HTML, CSS-only motion, icon sizes, …).
5. Build. Then compare the result to those examples, not to a generic SaaS
   card kit.

## Rules

- Cite the live page, not a remembered ranking. Galleries churn.
- Prefer MIT/open icon sets at 16/20/24 px when the UI is small
  (`https://gentleface.com`).
- Commercial generators (one-prompt site builders, paid template shops) are
  optional references. Do not install them or paste their paywalled kits
  into a toolkit.
- Do not copy a gallery piece into the project. Steal structure and craft,
  then draw original UI.
